# 移植差异与代码导航

## 业务层保留范围

学长工程的 `MDK-ARM`、`Robot` 文件仍在相同名称的目录中；用于本次固件的核心文件
也继续保持原文件名：`PID_task.c/.h`、`Auto.c/.h`、`task_init.c/.h`、`ramp.c/.h`
以及 `CANDrive`、`Chassis`、`motor`、`PID`、`wheel`、`CRC`。

根目录 `原工程业务代码对照/` 保存了迁移前副本，便于逐文件比较。注释中的
`【逐行 N】` 指向添加详注前的原始行号。

移植后已对核心逻辑做去注释/预处理对比：`Remote_deal` 的状态流程与原工程
一致；`Auto.c` 在将新 TIM2 寄存器映射回原 TIM1 名称后逻辑一致；`PID_Task`
的差异只落在已确认的按钮、USB CDC、FDCAN1 及 BMI088 接入点。

## 必须变化的硬件适配

| 学长 F407 工程 | MC02 H723 工程 | 控制层影响 |
|---|---|---|
| bxCAN2 控制五个电机 | FDCAN1 控制 `0x201`～`0x205` | 电机结构和 PID 不变 |
| bxCAN1 开启未实用 | FDCAN2 开启未实用 | 无业务数据 |
| USART2 + CH340 视觉 | Type-C USB CDC | `Data1Pack//Sequence` 保留 |
| USART3 + JY61 | 板载 BMI088 + Mahony | 输出仍为 `Now_Yaw/Now_Omega` |
| UART4 遥控器 | 移除 | 唯一明确的业务例外 |
| 遥控器按键启动 | PE2 常开复位按钮 | 仍把 `start` 置为 2 |
| TIM1_CH1/CH2 步进 | TIM2_CH1/CH3，PA0/PA2 | `StepCounter/Dir` 保留 |
| TIM4_CH1 舵机 | TIM1_CH1，PE9 | 比较值和动作宏保留 |
| 原步进 EN GPIO | 驱动器外部固定使能 | 原 EN 宏保留为空操作 |

## IMU 控制层接口

`App/imu_task.c` 每 1 ms 读取 BMI088：

- `Now_Yaw`：`float`，单位 `0.01°`，第一帧为零并做多圈展开；
- `Now_Omega`：`int16_t`，单位 `0.01°/s`，从 BMI088 Z 轴 `rad/s` 转换并限幅；
- `ImuReady`：BMI088 初始化且取得第一帧后为 1。

学长原工程声明了 `Now_Omega`，但没有找到给它赋值的代码，这是原工程缺陷，不可能
在改用 BMI088 后继续保持“永远为 0”。本移植保留其名字和类型，补上了有物理意义
的 `0.01°/s` 数据，使原 Yaw 速度环能够工作。

IMU 的机械安装方向无法仅由源码确定。默认在 `App/inc/imu_task.h` 中令
`IMU_YAW_SIGN`、`IMU_GYRO_SIGN` 均为 `-1.0f`。装车悬空测试时若转向闭环变成正反馈，
只修改这两个宏的符号，不要先改 PID 参数。

## USB 视觉适配

`MDK-ARM/vision_usb.c` 接收字节流，支持 USB 拆包、粘包和重新找帧头。协议保持学长
上位机格式：

```text
5A | 功能码 | ID(uint16小端) | 长度(uint16小端) | 负载 | CRC16
```

功能码 0 更新 `Data2.ex/ey`；功能码 1 更新六字节 `Sequence` 并置位 `ScreenGo`。
为了与学长现有上位机一致，接收端保留其行为：识别帧长度但不强制拒绝 CRC 错误帧。

上位机修改文件和 udev 说明在 `上位机_USB_CDC修改/`。

## 学长业务代码中继承的警告

GCC 能完整生成固件，但更严格的静态警告发现两处学长原算法中的未初始化变量：

- `AutoArmPos()` 中 `Temp0` 在部分分支可能未赋值就参与判断；
- `PutDouble()` 中局部变量 `Height` 可能未赋值就参与计算。

为兑现“运行逻辑完全一致”，本次没有擅自给它们补默认值。`PutDouble()` 当前没有在
自动主流程中直接找到调用，但仍建议机械联调前单独确认这两段的原设计意图，再决定
是否修正。编译器还提示原 `limit` 宏由多条语句组成，在无大括号 `if (put)` 后使用时
只有第一条受条件控制；这同样按原逻辑保留。
